Initial implementation of nodeakt, a high-performance actor library for Node.js.

**Actor model core.** An `ActorSystem` hosts the actor tree, one logical system per machine. Actors implement `preStart`, `receive`, and `postStop`; every actor is addressed through its `PID` under a `nodeakt://system@host:port/name` path, receives a `PostStart` announcement as its first message, and processes messages strictly one at a time, awaiting asynchronous behaviors before dequeuing the next message. Top-level actors are created with `system.spawn` and resolved with `system.actorOf`; a guardian hierarchy supervises the runtime's own actors separately from user actors.

**Messaging.** `tell` is fire and forget and returns `Error | null` on the synchronous hot path. `ask` delivers a message and returns a promise settled by the receiver's `ctx.response(value)`, with a per-call timeout. Messages sent from outside an actor are attributed to the system's `NoSender` actor, so `ctx.sender` is always comparable by identity. `ReceiveContext` also carries `forward`, child management, and death watch.

**PipeTo.** `pipeTo(to, task, opts?)` and `pipeToName(name, task, opts?)`, on both `ReceiveContext` and `PID`, run an asynchronous task off the actor's message loop and deliver its result back as an ordinary message, so the actor keeps handling other messages while the work is in flight and the result still arrives on the target's own turn. The task is a promise or a thunk returning one, the thunk receiving an `AbortSignal` that fires when the optional `PipeOptions.timeout` expires. The piping actor is recorded as the sender. A pipe never throws and a failing pipe delivers nothing: a dead target, a rejected task, and an expired timeout all route to dead letters carrying the failing reason (`ErrPipeTimeout` on timeout, `ErrUndefinedTask` for a missing task); to receive a failure as a message instead, map the rejection to a message class before piping. Stopping the actor does not cancel an in-flight task, and because the task runs off the actor's turn it must not read or mutate actor state.

**Scheduling.** `schedule(message, pid, interval, opts?)` delivers a message on a repeating interval and `scheduleOnce(message, pid, delay, opts?)` delivers one once after a delay; `cancelSchedule` / `pauseSchedule` / `resumeSchedule` control a schedule by the `reference` supplied in `ScheduleOptions`, and references live in one flat system-wide namespace. The same six methods exist on `ReceiveContext`, where a schedule is additionally owned by the scheduling actor and cancelled when that actor stops (replacing the `postStop` timer cleanup that is easy to forget), and the delivered message is attributed to the scheduling actor by default. Every tick goes through the normal send path: a tick to an actor that has stopped by fire time becomes a dead letter, a delivery counts as activity so a repeating schedule keeps a time-passivated actor alive, and every tick is an independent send with no overlap suppression. Schedules are owned by the system and die with it, so `system.stop()` leaks no timers. Internally all schedules share one unreferenced timer over a min-heap of absolute deadlines, the same approach passivation uses, so a large number of schedules stays cheap and pending schedules never keep the process alive. Every method is asynchronous and rejects with typed sentinels (`ErrActorSystemNotStarted`, `ErrInvalidInterval`, `ErrScheduleAlreadyExists`, `ErrScheduleNotFound`, and `ErrDead` for a target that has already stopped). Cron-expression schedules are not included yet.

**Behaviors and stashing.** `become` / `becomeStacked` / `unBecome` / `unBecomeStacked` switch an actor's message handler at runtime; `stash` / `unstash` / `unstashAll` buffer messages for re-delivery in arrival order.

**Hierarchy and lifecycle.** Actors spawn children with `spawnChild`; children stop with their parent. Graceful `shutdown` drains the accepted backlog, runs `postStop`, stops children first, and notifies watchers with `Terminated`. `restart` re-initializes an actor through its lifecycle hooks while keeping its queued messages; `reinstate` lifts a suspension in place. `PoisonPill` requests a graceful stop through the mailbox.

**Supervision.** A failing behavior suspends the actor and asks its parent for a decision. `Supervisor` maps error classes to directives (`stop`, `resume`, `restart`, `escalate`) under a `oneForOne` or `oneForAll` strategy, with retry budgets, exponential backoff, and a reset window. Escalation surfaces a `PanicSignal` to the grandparent's behavior; unsupervised guardians stop the system.

**Passivation.** Idle actors can be stopped automatically: `TimeBasedStrategy` schedules all participants on one shared unreferenced timer through a min-heap of deadlines, `MessagesCountBasedStrategy` stops an actor after a message budget, and the default `LongLivedStrategy` never passivates.

**Mailboxes.** The default `UnboundedMailbox` is a growable ring buffer that releases small buffers when an actor goes idle after start-up. `BoundedMailbox` rejects at capacity with `ErrMailboxFull`. `UnboundedSegmentedMailbox` stores the queue in linked fixed-size segments. `UnboundedFairMailbox` round-robins across per-sender sub-queues. Four priority mailboxes (`bounded` / `unbounded`, stable / unstable) order messages with a caller-supplied priority function, the stable variants preserving FIFO order among equal priorities.

**Reentrancy.** Actors spawned with a reentrancy configuration issue non-parking requests with `ctx.request(to, message, options)`: the call returns a `RequestCall` handle immediately, and the continuation registered with `onReply` runs on the requesting actor's own turn once the reply arrives, serialized with its message processing. `allowAll` keeps processing every message while replies are in flight, which also makes self-requests and call cycles (A requests B, B requests A) deadlock-free; `stashNonReentrant` stashes user messages until the last stash-mode request completes, preserving strict ordering while replies and runtime messages keep flowing. Requests support per-call timeout and mode overrides, cancellation with `cancel()`, and a per-actor `maxInFlight` cap; admission and delivery failures complete the handle with typed sentinels (`ErrReentrancyDisabled`, `ErrInvalidReentrancyMode`, `ErrReentrancyInFlightLimit`, `ErrRequestCanceled`). The handle is deliberately not awaitable: awaiting would park the behavior and resume outside the actor's turn, which is what a request avoids.

**Dead letters and the event stream.** A message the runtime cannot hand to its receiver (the target is not running, or its mailbox rejected the delivery, across tell, ask, and request) becomes a `Deadletter` event: sender and receiver paths, the message, the send time, and the failing reason. Dead letters flow through a runtime-spawned dead-letter actor into the system's event stream; subscribe with `system.subscribe(subscriber)` / `unsubscribe`, where the subscriber narrows events with `instanceof` the way `receive` narrows messages. An actor can also route an expected-but-unknown message there explicitly with `ctx.unhandled()`, which carries `ErrUnhandled` and does not engage supervision. Runtime announcements never become dead letters. The generic topic-based `EventStream` (subscribe, unsubscribe, publish, broadcast, close, with throwing subscribers contained) ships as its own module and will carry future runtime events.

**Cross-isolate groundwork (internal).** The runtime ships the seam that multi-core dispatch plugs into, as internal plumbing rather than public API. A structured-cloneable `Envelope` is the wire unit of every future transport: kind, target path and incarnation, sender path, correlation id, timeout, and a payload or an error. A `MessageRegistry` maps message classes to stable type ids, and the v0 codec stamps outgoing messages with their id, restores class prototypes on arrival so `instanceof` narrowing survives the boundary, refuses unregistered classes on the sending side, and carries the runtime's sentinel errors by index so identity comparison holds across a hop. A port transport proves the contract under test, carrying tell, ask, and request over a `MessagePort` channel: every payload passes through the codec and a real structured-clone hop, replies correlate by id through a pending table riding the shared timeout wheel, and undeliverable envelopes become dead letters. On top of it, an internal worker pool runs actors across real `worker_threads` isolates, one per core by default (`os.availableParallelism`), with round-robin placement of data-only actor recipes, full-mesh wiring, and worker-death cleanup. A shared registration-setup module keeps message classes and type ids aligned across every isolate; a payload the receiving isolate cannot decode fails the ask or dead-letters the tell instead of crashing the isolate; `ArrayBuffer`s in cross-isolate payloads are transferred rather than copied; a placed actor's top-level name frees again when the actor stops; and worker facades forward their dead letters to the main system's event stream, so one subscription observes the whole logical system. One addressed handle serves both worlds: `ActorRef` resolves on its own isolate's tree or sends through an isolate route, indistinguishably to the caller. Recipe loading is fenced to file modules that export a real actor class, and optional per-worker resource limits contain a runaway isolate to its own death instead of the process's. The bundled scaling benchmark measures CPU-bound speedup approaching the machine's real parallel throughput (5.5x on 8 logical cores split into 4 performance and 4 efficiency cores).

**Multi-core.** The framework now scales itself to the machine, invisibly: `ActorSystem.start()` on a one-core box runs exactly the single-isolate runtime, and the same program on an N-core box spreads placed actors over one V8 isolate per core (`os.availableParallelism`, cgroup-aware), with `ActorSystemOptions.parallelism` as the one operational override. The public surface is four names. `Props.create(ActorClass, ...args)` captures actor construction as data, with the constructor arguments checked by the compiler; passing it to the unchanged `spawn(name, actor, options?)` slot lets the runtime build the actor on whichever core it chooses, while the instance form stays local, exactly as before. `registerActor(ActorClass)` records at module scope where an actor's code lives (the module URL is inferred from the call site through `util.getCallSites`; pass `import.meta.url` explicitly from registration wrappers), and `registerMessage(MessageClass)` registers the message classes that may cross isolates; registration is self-propagating, because any isolate that imports the module runs the same lines. Everything else gains reach without changing shape: `actorOf` resolves names on any core to a PID-shaped routed handle, `tell`/`ask`/`request` through it are indistinguishable from the local forms, replying to `ctx.sender` routes back to whichever core the sender lives on, and `watch` delivers `Terminated` across cores, including when a whole worker dies (watching an already-stopped actor across cores answers immediately, the Erlang and Akka semantics). Top-level names are unique across the machine through one control-plane authority, consulted by `spawn` and `actorOf` on the main isolate and on every worker facade. Failures are loud and placement-independent: unregistered classes reject with `ActorNotRegisteredError`, uncloneable constructor arguments and live-object spawn options (`mailbox`, `supervisor`, `passivationStrategy`) are refused for every `Props` spawn (`reentrancy`, being data, crosses fine). Recipe imports are fenced by the framework with no knob to set: placement only ever loads a module a `registerActor` call recorded, through `file:` URLs and plain paths alone, so `parallelism` is the single operational override. The pool boots lazily on the first `Props` spawn and never boots at parallelism 1, so nobody pays for cores they do not use; the local send paths keep their measured numbers (20M+ tells/sec, 5M+ ask round trips/sec). Worker-thread dispatch plugs in behind this seam unchanged; network remoting is a separate future feature that reuses the envelope semantics and type registry with its own wire codec.

**Logging.** A structured `Logger` interface with `debug` / `info` / `warn` / `error` levels, per-entry fields, lazily computed payloads that are never built when the level is disabled, and `with(fields)` child loggers that bind stable context. The default `JsonLogger` writes one JSON line per entry to standard error at info level, serializing errors as name, message, and stack and surviving unserializable payloads; `discardLogger` silences the runtime entirely. Configure per system with `new ActorSystem(name, { logger })`; the runtime reports through it, and lifecycle hooks reach it via `ctx.logger()`.

**Errors.** Failures are typed sentinels (`ErrDead`, `ErrMailboxFull`, `ErrRequestTimeout`, `ErrActorAlreadyExists`, and friends) compared by identity; asynchronous APIs reject with them, the synchronous send path returns them.

**Performance.** Measured on a single event loop with the bundled benchmark suite: 23M+ tells/sec for a single producer and consumer pair, 24M+ across independent pairs, at 50 bytes allocated per message; 5.6M ask round trips/sec sequential, 7.2M with 10,000 in flight, 8.2M with concurrent askers; idle actors occupy under 512 bytes of heap each, about 0.4 GB per million actors. The receive loop stays fully synchronous while behaviors do, message processing yields to the event loop every 2048 messages, mailbox rings survive between bursts, and pending asks share one unreferenced timer per timeout duration instead of a timer object per call.

Two contracts worth knowing:

- The ask `timeout` is a lower bound with coarse expiry: an unanswered ask is rejected between one and two timeout periods after it was sent. Answered asks are unaffected.
- Receive contexts are managed by the runtime and may be reused once `receive` has fully settled. Call `response` before the behavior finishes and do not retain a context beyond the current message; holding a context to answer it during a later message remains supported while the ask is unanswered.
